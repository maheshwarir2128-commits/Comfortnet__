# ComfortNet Backend — Phase 2 Software Foundation

**Status: software prototype. No physical hardware, MQTT broker, or AI/ML model exists.**
Every telemetry value in this system is generated by `simulator/simulate_telemetry.py`, never read from a real sensor.

## What this is

A FastAPI backend implementing the API contract from the Phase 2 Architecture Specification, plus:
- A deterministic, demo-controllable simulated telemetry generator (no real hardware)
- Rule-based explainable analytics (node health score + anomaly detection) — **not AI/ML**, clearly labeled as such in every API response
- A `/demo/scenario` control endpoint so a presenter can trigger LOW BATTERY / SENSOR ANOMALY / NETWORK FAILURE / SOS EVENT / RECOVERY on demand, so the demo never depends on luck

## Install

```bash
cd comfortnet-backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Run

```bash
uvicorn app.main:app --reload --port 8000
```
Then open http://localhost:8000/docs for interactive API docs, or http://localhost:8000/health for a live status summary.

On first run, the backend auto-creates `comfortnet_dev.db` (SQLite) and seeds one demo campus (`demo-campus`) and three demo nodes (`tree-01`, `tree-02`, `tree-03`).

## Run the simulator (separate terminal, backend must already be running)

```bash
source venv/bin/activate
python simulator/simulate_telemetry.py
```
This posts telemetry for `tree-01`, `tree-02`, `tree-03` every 5 seconds (configurable), with a full simulated day/night solar cycle compressed into 10 minutes of real time.

## Trigger a demo scenario

```bash
curl -X POST http://localhost:8000/demo/scenario -H "Content-Type: application/json" -d '{"scenario": "low_battery"}'
```
Allowed values: `normal`, `low_battery`, `sensor_anomaly`, `network_failure`, `sos_event`, `recovery`.
The simulator polls this every tick and adjusts what it generates — the running simulator does not need to be restarted.

## Test

```bash
source venv/bin/activate
pytest -v
```
**NOT EXECUTED IN THIS BUILD ENVIRONMENT** — the sandbox this backend was written in has no network access to install fastapi/sqlalchemy/pytest, so these tests are syntax-checked (`py_compile`) but not run. Run `pytest -v` locally to actually execute them; 23 tests are provided across health, nodes, telemetry, alerts, and analytics.

## What is NOT implemented (do not claim otherwise in a demo)

- Physical ESP32-S3 / Raspberry Pi / solar / battery / sensors / camera / GPS / SOS button
- MQTT broker (this backend uses direct HTTP ingestion from the simulator — a documented development choice, since Phase 2 marks MQTT as PROPOSED, not built)
- Real authentication (`/auth` is an explicit, labeled placeholder)
- Predictive-maintenance AI/ML (the `/analytics/*` endpoints are rule-based and say so in every response)
- Production database, production security, production deployment
- Any field/hardware validation

## Known limitations

- Demo scenario state (`/demo/scenario`) is in-memory and resets on backend restart.
- SQLite is a development choice, not a production decision (see `app/config.py`).
- `/auth` does not gate any other endpoint in this build — every other route is currently open, appropriate for a local demo only.
- This backend was built and syntax-checked in a sandboxed environment without network/package-install access. It has not been run end-to-end by Claude — run it locally using the commands above before your first demo rehearsal.
